# YDS 사이트

YBM 디자인 시스템 공식 문서 사이트를 준비하는 폴더다. 2026-10-30 별도 저장소(ybm-ds-site)에서 yds 저장소 안 `site/` 로 합쳤다. DS 를 사이트로 보여 주는 것이라 한 저장소로 관리한다.

## 현재 상태
- 사이트 주소: <https://luvms012-rgb.github.io/yds/site/> (로컬 미리보기는 works/.claude/launch.json 의 ds-preview → http://localhost:5179/site/)
- **만들기: `node site/build.mjs`** - 바로 위 폴더(DS)의 components.json, dist/components.css 머리 주석과 --ds-* 변수, tokens.css, icons.css, ybm-ds.js 머리 주석, 루트 index.html 예시, README 6.2 지침을 읽어 페이지를 만든다. DS 를 고치면 다시 실행만 하면 된다.
- 손으로 쓰는 것: `site/build.mjs`(시작하기, 사용 규칙 문장 포함), `site/src/`(site.css, site.js, logo-mark.svg, figma-notes.json, templates.json), `site/templates/gen/*.mjs`(템플릿 생성기, pages/*.html 은 생성물)
- 생성물(직접 고치지 않음): `site/index.html`, `site/get-started/`, `site/components/`, `site/templates/*.html`, `site/assets/`
- `site/src/figma-notes.json`: Figma 컴포넌트 설명에서 옮긴 페이지 분류, 한 줄 설명, Do/Don't. Figma 설명을 고치면 같이 고친다.
- 부족한 정책/가이드 제안: [PROPOSAL.md](PROPOSAL.md) - 사용자가 검토 후 고른 것만 추가한다.
- 먼저 읽을 문서: REFERENCE-ANALYSIS.md(레퍼런스 A, B 분석, **로컬 전용** git 제외)

## 사용자가 확정한 것
- **Updates > 요청 탭 (2026-11-14 사용자 "요청 현황 공개", "추천대로")**: Updates 안에 소식 / 요청 두 탭(`updates.html`, `updates-requests.html`, build.mjs `updTabs`). 요청 목록은 `site/src/requests.json` 한 파일이고 담당자가 의견 보내기 폼 응답을 보고 고친다(사용자가 "이 요청 추가", "반영됨으로" 라고 하면 Claude 가 파일을 고쳐 배포). 같은 요청은 줄을 늘리지 않고 count 를 올린다. 요청한 사람 이름은 적지 않고 소속만. 상태는 접수, 검토 중, 반영됨, 보류(순서도 이대로, 반영됨은 최근 반영 먼저). 표 위에는 의견 보내기 버튼 하나만. 요청 현황은 Updates 안에서만 보인다(푸터 링크는 넣었다가 사용자 "푸터에 요청 현황 제거" 로 뺐다). 새 소식이나 새 요청이 있으면 Updates 메뉴에 표시하고, Updates 안에서는 새 내용이 있는 탭에 점을 찍는다(site.js "새 소식 표시", localStorage 소식 ybm-site-updates-seen, 요청 ybm-site-requests-seen, 요청 목록이 바뀌면 build.mjs `LATEST_REQUEST` 가 바뀐다). 요청이 반영되면 DS 변경일 때만 Updates 소식에도 한 줄(소식 규칙 그대로). 처음 내용은 실제 요청 5건(반영됨 4, 검토 중 1). 2026-11-14 사용자 "요청 오늘 기준 모두 삭제" 로 5건을 모두 지웠다(되돌리려면 git 기록). 목록이 비면 표 대신 Empty "아직 들어온 요청이 없습니다" 를 보이고, 새 요청 점은 띄우지 않는다(LATEST_REQUEST 빈 값).

- **한글 쓰기 규칙** (2026-11-02 회사, 사용자 "레퍼런스 B 전체를 검수해서 한글을 그대로 우리 쪽에, 가급적 한글로". 레퍼런스 B 의 글쓰기, 말투 문서와 시작하기, 컴포넌트 문서 표본에서 뽑음):
  1. 이름은 영어 그대로: 상단 메뉴, 왼쪽 메뉴, 페이지 제목(Get Started, Usage, Color, 컴포넌트 이름), 토큰, 클래스, 속성 이름, Figma. 영어 뒤 조사는 바로 붙인다(Button은, `data-size`를).
  2. 나머지는 한국어: 섹션 제목(h2, h3)과 목차, 버튼, 탭, 표 머리, 찾기 칸 안내, 분류 칩. 시작하기 문서 제목은 "개요", "설치하기", "컴포넌트", "다크 모드" 처럼 짧게(군더더기 "첫", "켜기" 같은 말은 빼기, 11-02 사용자). Do / Don't 표시만 영어로 둔다(레퍼런스 B 도 그렇다).
  3. 문서 글(리드, 본문, 표 안 설명, 사용 지침, 템플릿 설명)은 합니다체. "~있어요, ~해요" 를 섞지 않는다. 안내는 "~하세요".
  4. 화면 글(예시, 대표 그림, 템플릿 안, 빈 결과 안내)은 해요체. 쉬운 말, 아라비아 숫자, 높임은 최소("~하실" 대신 "~할"), "불가능합니다" 대신 "할 수 없어요", 오류는 고치는 방법까지, 주의와 경고만 "~니다".
  5. 제목, 버튼, 메뉴, 라벨, 표 머리에는 마침표를 찍지 않고 문장에는 찍는다. 느낌표, 줄임말, 어려운 한자어는 쓰지 않는다.
  6. (2026-11-03 국내 DS 사이트 SEED, KRDS, LINE, Montage 검토로 보강) 설명은 하는 일을 바로 말하고 "~하게 하는 컴포넌트" 를 되풀이하지 않는다. 버튼, 창, 칸, 표처럼 무엇인지 드러나는 말로 끝맺어도 된다. 템플릿 설명은 화면 안 요소를 늘어놓지 말고 "어떤 화면인지 + 언제 쓰는지" 한두 문장.
  6-1. 설명(리드)은 하는 일로 쓴다(2026-11-02 사용자 "디스크립션도 seed 처럼"): 컴포넌트는 "누르면 ~하게 하는 컴포넌트입니다.", Foundations 는 "색은 ~를 보여 주도록 돕습니다." 처럼 주제어로 시작, 안내 페이지는 "~를 알아봅니다." 생김새나 토큰 목록 나열("~토큰입니다", "작은 그림입니다")로 쓰지 않는다. 컴포넌트 설명 원본은 figma-notes.json lead(71개 모두, Figma 문서 프레임 설명은 최종 검토 때 맞춘다).
  - 템플릿 분류 칩은 보이는 이름만 한국어(build.mjs `TPL_GROUP_KO`), 거르는 값은 templates.json 의 영어 group 그대로.

- **Themes 는 숨김** (2026-11-05 사용자 "테마는 아직 쓰기엔 부족하다, 우선 전체 숨김"): build.mjs `SHOW_THEMES = false`. 테마 CSS 10개(dist/themes)와 테마를 입힌 화면 10개(site/themes/pages)는 `site/themes/gen.mjs` 하나가 만든다. 고치면 `node site/themes/gen.mjs` → `node site/build.mjs`. 레퍼런스 서비스 이름은 저장소에 적지 않는다. 다시 켜자고 하기 전에는 제안하지 않는다.
- **AI 용 마크다운** (2026-11-03 회사, 사용자 "md 도 배포, 컴포넌트 단위 등 글로벌 케이스로"): llms.txt 표준(llmstxt.org)과 레퍼런스 B 의 페이지별 LLMS.txt 메뉴를 따라, 시작하기/Foundations/컴포넌트 페이지마다 같은 주소의 `.md`, 전체 목차 `site/llms.txt`, 전체 한 파일 `site/llms-full.txt`. `site/md.mjs` 가 생성된 HTML 본문을 마크다운으로 바꾼다(미리보기, 버튼, 메뉴 제외, 예시 코드는 포함). 제목 아래 버튼 줄(Figma, 코드 옆)에 Markdown 메뉴(DS Menu): 링크 복사, 내용 복사, 새 창으로 열기, 전체 목차. 시작하기 > Guide > AI 페이지에 쓰는 법과 요청 예시. llms.txt 끝에 Templates(템플릿 HTML 원본 주소 + 설명), Themes(테마 CSS 주소 + 설명) 목록을 붙인다(md.mjs `extra`). .md 안 링크는 .md 가 있는 페이지만 .md 로 바꾸고 템플릿, 테마는 .html 그대로.
